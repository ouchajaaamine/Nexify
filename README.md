## 💡 What is it?

**Nexify** helps marketing teams follow their campaigns in one place: budget, revenue, ROI, conversions and affiliates. It also includes an **AI assistant** you can question in plain language.

The project covers the whole chain, from code to cloud:

- a **Next.js 15 / React 19** front end;
- a **Symfony 7 / API Platform** REST API secured with **JWT**;
- an AI assistant built on **Google Gemini**, with a **Redis** cache;
- a **Jenkins** pipeline with parallel quality checks and **Trivy** security scans;
- deployment on **AWS EKS**, with images stored in **Amazon ECR**.

## 🤖 AI assistant

The assistant is not a simple API call: it is built to stay **useful, fast and available**.

```mermaid
flowchart LR
    Q[💬 User question<br/>+ campaign data] --> C{Redis cache<br/>10 min}
    C -- hit --> R[⚡ Instant answer]
    C -- miss --> P[🧩 Prompt built with<br/>campaign context]
    P --> G[🔁 Gemini model chain<br/>2.5 Flash → 2.5 Pro → 2.0 → 1.5 …]
    G -- success --> R
    G -- all models fail --> F[🛟 Local fallback answer]
```

- **Context-aware**: the campaign's data is injected into the prompt, so answers are based on real figures.
- **Resilient**: the service lists the Gemini models available to the API key, then tries them in order of preference until one answers.
- **Fast and cheaper**: identical questions are served from **Redis** for 10 minutes.
- **Never broken**: if Gemini cannot be reached, the assistant still returns a fallback answer instead of an error.
- **Tested**: covered by PHPUnit unit tests.

## 🏗 Architecture

```mermaid
flowchart LR
    user([👤 User]) --> fe

    subgraph eks [☸️ AWS EKS · eu-west-3]
        fe[⚛️ Frontend<br/>Next.js 15 · 2 replicas]
        be[🎼 Backend API<br/>Symfony 7 · API Platform<br/>Nginx + PHP-FPM · 2 replicas]
        db[(🐘 PostgreSQL 16<br/>persistent volume)]
        cache[(🟥 Redis 7)]
    end

    fe -->|REST + JWT| be
    be --> db
    be --> cache
    be -->|HTTPS| gemini[✨ Google Gemini API]
```

- **Separate services**: the front end and the back end are deployed and scaled independently.
- **API-first**: entities exposed by API Platform, with search filters and OpenAPI docs.
- **Versioned schema**: database changes are managed with Doctrine migrations.
- **Production-ready pods**: liveness and readiness probes, CPU and memory requests and limits.

## 🔄 CI/CD pipeline

A **Jenkins** pipeline takes every change from commit to production on EKS:

![Jenkins pipeline](./screenshots/pipeline.png)

```mermaid
flowchart LR
    A[📥 Checkout] --> B

    subgraph B [⚡ In parallel]
        B1[🎼 Backend<br/>Composer · PHPStan · PHPUnit]
        B2[⚛️ Frontend<br/>pnpm · Next.js build]
        B3[🛡 Trivy<br/>dependency scan]
    end

    B --> C[🐳 Docker images<br/>backend + frontend]
    C --> D[🛡 Trivy<br/>image scan]
    D --> E[📦 Amazon ECR<br/>tag: commit SHA + latest]
    E --> F[☸️ Deploy to EKS<br/>kubectl apply + rollout status]
```

- **Parallel stages**: back-end checks, front-end build and security scans run at the same time.
- **Quality**: PHPStan static analysis and PHPUnit tests, with JUnit reports published in Jenkins.
- **Security**: Trivy scans the dependencies and then the final Docker images, and the reports are archived with each build.
- **Traceability**: every image is tagged with its **commit SHA**, so you can roll back to any version.
- **Safe rollout**: the pipeline waits for `kubectl rollout status` before reporting a successful deployment.

## ☸️ Deployment on AWS EKS

The cluster is described in `k8s/eks-cluster.yaml` and created with **eksctl**:

- region **eu-west-3 (Paris)**, Kubernetes **1.32**, spread over 3 availability zones;
- managed node group of **t3.medium** instances, **2 to 4 nodes**, tagged for the Cluster Autoscaler;
- IAM add-on policies for autoscaling, EBS volumes and load balancers.

The application manifests are applied in order:

| Manifest | Content |
|---|---|
| `00-namespace.yaml` | `nexify` namespace |
| `01-configmap.yaml` | Application configuration |
| `02-secrets.yaml` | Application secrets |
| `03-postgres.yaml` | PostgreSQL 16 with a persistent volume |
| `04-redis.yaml` | Redis cache |
| `05-backend.yaml` | Symfony API, 2 replicas, LoadBalancer service |
| `06-frontend.yaml` | Next.js, 2 replicas, LoadBalancer service |

## 🚀 Run it locally

**Prerequisites:** Docker and Docker Compose.

```bash
git clone https://github.com/ouchajaaamine/Nexify.git
cd Nexify

# Optional: enables the AI assistant
echo "GOOGLE_API_KEY=your_key_here" > .env

docker compose up -d --build
docker compose exec app composer install
docker compose exec app php bin/console doctrine:migrations:migrate
docker compose exec app php bin/console doctrine:fixtures:load   # sample data
```

| Service | URL |
|---|---|
| Frontend | http://localhost:3000 |
| API | http://localhost:8000 |
| API documentation | http://localhost:8000/api |

> Without `GOOGLE_API_KEY` the application works normally, and the assistant answers in fallback mode. You can get a free key from [Google AI Studio](https://aistudio.google.com/).
